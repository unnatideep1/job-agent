# Writing style and tailoring rules (example: edit these with the candidate)

The Writer follows these rules and Tod checks against them. They override the skills.

## 1. Truth
- Every claim traces to `master_resume.yaml` (a bullet id) or to `confirmed_additions`.
- New information is welcome once the candidate confirms it. The Writer asks through the orchestrator, the answer is recorded in `confirmed_additions` with an id, and only then is it used, as an `additions` entry.
- Never inflate a metric, change a date, merge two products, or relabel a product's type (B2B vs B2C) beyond what the master file says.
- Claims about outcomes are fine only if the candidate can back them up in an interview. If unsure, ask.

## 2. Reframe existing material first
- Mirror the posting's language when it describes the same thing the candidate did.
- Lead with the facts the posting ranks highest, in the JD's own order.
- Reword for relevance and keep the meaning. A reframed bullet must stay factually true (same facts and numbers); its wording and structure should change to fit the JD.

## 3. Think like a job seeker: gap analysis
For every JD requirement, mark it Proven, Partly proven or Missing. For each gap, ask one specific question, for example: "The JD asks for SQL and dashboards. Have you written SQL or built dashboards? Where, and for what?"

Also flag risks a screening tool will compute, such as years in the function below the asked minimum, and suggest how to handle each one: a referral, an outreach note, or an interview answer.

## 4. Structure
- Each role's first bullet is its scope bullet and stays first.
- Sub-products stay separate, each under its own heading, exactly as in the master file.
- Keep every role. Shorten older roles with `omit` only when needed to fit the page limit.
- Use titles exactly as held.

## 5. Summary
- Keep it to the point, not a story, with no narrative connectors.
- No filler or try-hard phrases ("passionate", "rockstar", "hands-on with X" as a slogan).
- Lead with scope, outcomes and numbers.
- If the candidate supplies summary text, use it as given. Fix only typos and clear grammar slips, and say what you fixed.

## 6. Core Strengths
- Pick and order them from `strengths_library` to match the JD's priorities.
- Don't add tool names or techniques unless the candidate asks.
- Lead with what the JD leads with, not with the candidate's favourite story.

## 7. Scope of edits
- Change only the resume the candidate names.
- After any edit, report exactly what changed.

## 8. ATS and screening agents
- Use the JD's key terms wherever they're true.
- The text layer must read in order: company, title, dates, then bullets. The builder checks this.

## 9. Tailoring depth (what "tailored" means)
- Reordering is not tailoring. Every page-1 bullet should be rewritten so it opens with what it proves for this JD, in the JD's vocabulary, unless it already does.
- Keep the facts: same numbers, same scope, nothing the candidate didn't do. Rewording, restructuring, and choosing which detail to lead with are expected.
- Roles that are less relevant to this JD can stay close to the master.
- Plain words only. No vague labels (e.g. "AI quality", "synergies", "leveraged"): say what was actually done.

## 10. Summary coherence
- The summary is one argument for this job: who the candidate is, the proof, and why it matters to this role. Each sentence must follow from the last.
- If it names a count ("three products"), it names all of them, briefly and in a consistent way. No abrupt jumps into one product's details.
- Not only the current employer: it should carry the career thread the JD cares about.

## 11. Lessons from candidate feedback
- Don't repeat a phrase back-to-back (e.g. "0→1" twice in a row).
- When listing items (products, roles), give each equal weight; don't deep-dive one of them in the summary.
- Default summary shape: who → what was built (all items named briefly) → earlier career line → results, framed around what the JD values (e.g. analytics).
- Sell analytical work as analytical: evaluation, benchmarking, ML research direction, dashboards.
- Attribute every number to the exact product or role it came from.
